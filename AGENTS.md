# AGENTS.md — инструкция для AI-агента, ведущего этот проект

Этот файл читать ПЕРВЫМ, до любых изменений. Затем прочитать
`PROGRESS.md` — там актуальное состояние и планы.

## Проект одним абзацем

PAPER grid-бот на Python (asyncio + aiogram 3 + pybit). Берёт реальные
цены Bybit Spot (публичный API, ключи НЕ нужны), торгует виртуальными
деньгами, управляется через Telegram. Деплоится на Railway как worker.
Версия кода: 3.0 (см. PROGRESS.md).

## Правила работы с кодом

1. **Только латиница в комментариях `telegram_bot.py` и `paper_bot.py`.**
   Файлы пересылаются с телефона — не-латиница ломает кодировку.
   README/AGENTS/PROGRESS пишутся нормальным русским.
2. Конфигурация — ТОЛЬКО через переменные окружения (`config.py`,
   `os.getenv`). Никаких захардкоженных токенов и ключей. Реальных
   API-ключей биржи в проекте нет и не должно быть (PAPER-режим).
3. Секреты (`TELEGRAM_TOKEN`, `ADMIN_ID`) живут в Railway → Variables,
   в код не вставлять.
4. Любое изменение: сначала прочитать соответствующий файл целиком,
   менять минимально, не переписывать стиль.
5. После каждого изменения:
   - обновить версию в docstring изменённого файла (например 3.0 → 3.1);
   - записать изменение в `PROGRESS.md` (раздел «История» + актуализировать
     «Текущее состояние»);
   - выдать пользователю готовые команды `git add / commit / push`
     и напомнить: на Railway деплой происходит автоматически после пуша.
6. `state.json`, `trades.csv`, `bot.log` — генерируемые файлы,
   в коммиты не включать.

## Архитектура

- `main.py` — вход. Валидирует env, создаёт `PaperBroker` и
  `TelegramController`, авто-resume если `state["active"]` (введено в 3.0).
- `paper_bot.py` — ядро. Класс `PaperBroker`:
  настройки (`_eff`/`update_setting`), состояние (`_load_state/_save_state`),
  сетка (`build_grid`, `rebuild_grid`), исполнения (`check_fills`,
  `_execute_fill`, `_can_fill`), дайджест/просадка (`_daily_tick`,
  `_drawdown_check`), главный цикл (`loop`), статус.
  Уведомления — через колбэк `broker.notify`.
- `telegram_bot.py` — класс `TelegramController`: ReplyKeyboard-кнопки,
  inline-настройки (`set:<key>:<delta>`), отправка документов (Logi).
- Состояние — один `state.json` (балансы, ордера, open_buys, stats, day-*).
  На Railway должно быть `DATA_DIR=/data` + Volume `/data`, иначе состояние
  теряется при рестарте.

## Ключевые решения (не ломать без согласования с владельцем)

- Продажа без парной покупки = продажа инвентаря по `inv_cost`
  (себестоимость), не по рынку.
- Пробой сетки вниз = держим монету, rebuild НЕ делаем (только alert).
- Пробой вверх = rebuild от новой цены.
- Виртуальные ордера исполняются по цене уровня ± slippage.
- `build_grid()` сбрасывает балансы к фиксированному банку — см.
  известные ограничения в PROGRESS.md.

## Проверка изменений

- Локально (если есть Python 3.10+):
  `pip install -r requirements.txt`, затем задать `TELEGRAM_TOKEN`,
  `ADMIN_ID` и `python main.py`.
- PAPER-режим безопасен: реальных денег нет, можно экспериментировать.

## Контекст для нового агента (почему это работа с любого аккаунта Kimi)

Владелец ведёт проект с разных аккаунтов Kimi: лимиты одного аккаунта
заканчиваются — работа продолжается с другого. Поэтому вся «память» о
проекте хранится ЗДЕСЬ, в репозитории: этот файл (как работать) +
`PROGRESS.md` (что сделано и что дальше). Никакой контекст не живёт
в чате — при продолжении работы с нового аккаунта читайте эти файлы,
и вы сразу в курсе.
